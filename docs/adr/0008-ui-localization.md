# ADR 0008：界面多语言与语言一致性

## 状态

已采纳，2026-08-28。

## 决策

DSH Cyber 的界面语言是工作区级偏好，保存在 `workspace_preferences.locale`，并同步写入浏览器本地存储用于首屏启动。应用在 React 挂载前设置文档的 `lang`、`dir` 与 `data-locale`，避免刷新时先显示另一种语言。

首批支持以下常用语种：简体中文、繁体中文、英语、日语、韩语、西班牙语、法语、德语、巴西葡萄牙语、俄语、阿拉伯语和印地语。阿拉伯语启用 RTL 文档方向。新增语言必须同时更新合同、持久化约束、启动解析、语言元数据、全部消息目录和自动化测试。

界面消息使用稳定键，日期、时间、数字、列表和时长使用当前语言的 `Intl` 格式化。状态、权限、审批决定等协议枚举不得直接渲染；`WorkTurn`、`AgentRun`、`Artifact` 等内部术语只可作为技术标识或调试详情，不得混入普通产品文案。

服务端错误响应保留稳定 `code`，并提供 `messageKey`。前端按当前语言展示安全消息；不得把另一种语言的服务端原始错误直接显示给用户。角色或模型生成内容属于用户内容，不应伪装为已翻译的产品界面。

## 回退规则

每个支持的语言目录必须具备完整且非空的相同键集合。运行时仍按“当前语言 → 英语 → 简体中文 → 调用方兜底”解析，以便开发过程中可诊断；CI 的目录完整性测试负责阻止缺失翻译进入主分支。

## 验证要求

- 语言选择保存后，刷新、切换世界和服务重启均保持一致。
- 简体中文和英语核心流程不得出现另一语言的产品状态或操作文案。
- 阿拉伯语验证 RTL、键盘操作和布局不溢出。
- 自动化检查固定语言格式化、原始协议枚举渲染和 12 个目录的键完整性。
- 视觉回归覆盖 1440×900、1920×1080、3840×2160，并记录控制台错误与警告。
