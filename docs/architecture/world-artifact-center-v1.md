# 世界产物中心 V1

世界产物中心用于保存角色或用户明确发布的工作成果。显式运行清单始终优先；清单缺失时，宿主优先使用自己在运行前后对世界工作目录做的落盘观察，只有在没有可用观察记录时才退回按时间窗口挑选文件，并把这种结果明确标注为未验证。任何情况下都不根据聊天文字猜测产物，也不读取桌面或世界目录外的文件。

## 用户可见能力

- 右侧“产物”页按当前世界列出已发布成果，支持搜索、类型筛选、重命名、归档和版本查看。
- 聊天回复可以引用已登记的产物。点击产物卡会打开同一个世界中的产物详情。
- Markdown 使用文档阅读器显示标题、列表、引用、表格和代码块；代码、JSON、PDF、图片、HTML 和项目目录使用各自的阅读方式。
- HTML 预览运行在隔离沙箱中，不能访问 DSH Cyber 的应用接口或页面数据。
- 刷新页面或重启服务后，产物登记、版本和聊天引用仍可恢复。

“知识”页提供独立的原始资料库。产物不会自动进入知识库，只有用户明确执行“加入知识”时才建立带来源的知识文档。

## 权威数据与文件边界

SQLite 是产物身份、当前版本、状态、来源和运行关联的权威数据源。发布文件保存在对应世界目录中：

```text
<stateRoot>/worlds/<worldId>/
├─ files/                         # 世界工作目录
│  └─ .dsh/artifacts/             # 运行结束时写入的发布清单
├─ runs/evidence/                 # 宿主私有的落盘观察与证据等级
└─ exports/artifacts/
   └─ <artifactId>/v<version>/    # 不可变的已发布版本
```

工作目录与发布目录承担不同职责：

- `files/` 中的源文件可以继续编辑；
- `exports/artifacts/` 中的版本是发布时快照，不随源文件变化；
- 删除或归档登记不会把工作目录中的源文件当作缓存清理；
- 世界隔离由 `worldId`、世界根目录和数据库外键共同保证。

## 角色运行后的发布流程

每次角色运行结束后，编排层调用一个与模型供应商无关的完成钩子。钩子优先读取该次运行对应的精确清单：

```text
files/.dsh/artifacts/<agentRunId>.json
```

清单中的每一项必须声明工作目录相对路径、名称和类型，也可以声明说明和项目入口文件。服务端会在发布前重新验证：

- 路径必须位于当前世界工作目录内；
- `.dsh` 管理目录不能作为产物来源；
- 符号链接、目录穿越、超出大小或文件数量上限的内容会被拒绝；
- 项目入口必须是项目目录内的普通文件；
- 文件内容和摘要必须与写入数据库的版本一致。

清单中某一项缺失、超限或类型不符时，其余条目照常发布，失败项进入本轮完成结果的 `artifactFailures`；只有越界路径、符号链接和工作区越界会整体拒绝该清单，因为那说明请求本身不可信。

## 宿主可验证的落盘证据

角色运行时，宿主在把这一轮交给运行时之前和拿回结果之后各做一次有上限的工作目录普查（文件大小、修改时间、inode），记录写进世界目录下的宿主私有区域：

```text
<stateRoot>/worlds/<worldId>/runs/evidence/<agentRunId>.json          # 本轮落盘观察
<stateRoot>/worlds/<worldId>/runs/evidence/<agentRunId>.published.json # 每次发布的证据等级
```

这两个文件在 `files/` 之外，当前世界权限下的角色写不到，也随世界一起备份。观察记录同时保存同一世界中当时还在执行的其他运行，用来判断这次写入是否可以独占归属。

一次发布的证据等级只有六种：`host-observed`（宿主在本轮独占观察到这份内容落盘）、`shared-window`（观察到写入，但同一时刻另有运行，或运行结束后内容又变了）、`manifest-declared`（清单声明且文件真实存在，但没有落盘观察）、`unproven-window`（仅时间窗口匹配）、`owner-published`（用户手动发布）、`unknown`（观察记录已缺失）。只有第一种可以在界面上作为证据呈现。

如果该次运行没有写入清单，宿主优先使用未截断的落盘观察结果：观察为空是一个明确结论——本轮只回复了文字，没有文件落盘，此时不再退回时间窗口。只有在没有观察记录或普查触到上限时，才使用已持久化的 AgentRun 开始/完成时间收集变更文件，并整体标注为未验证。自动登记继续遵守同一世界、路径、符号链接、大小与数量限制；候选文件超过 32 个时不再登记，本轮完成结果里报告候选数量，而不是让整轮后处理失败。显式空清单表示本轮明确不发布，不触发自动登记。

宿主观察能证明的是：一份内容完全相同的普通文件，在这次运行的观察区间结束时存在，而区间开始时不存在或内容不同，并且没有其他被观察的运行覆盖这次写入时刻。它不能证明写入动作出自模型进程——同一区间内用户上传、外部编辑器或（完全访问模式下）任何其他程序的写入，对宿主来说是一样的。

发布顺序是“验证 → 复制到临时目录 → 生成摘要 → 原子切换版本目录 → 写入 SQLite”。重复处理同一个运行清单使用稳定幂等键，不会生成重复版本。只有发布成功后，最终聊天消息才会写入 `artifactRefs`。

## 阅读器安全边界

预览接口只允许读取已登记版本中的文件：

- Markdown、文本、代码和 JSON 以受限文本响应返回；
- 图片和 PDF 使用浏览器原生预览；
- 项目先返回受限文件树，点击文件后再按精确相对路径读取；
- HTML 响应带严格内容安全策略，前端 `iframe` 不授予同源权限。

原始 Prompt、模型隐藏推理、API 密钥、Cookie、Authorization、任意工具输入和未发布的工作区内容不会进入产物登记或预览响应。

## 备份、恢复与诊断

产物元数据随 SQLite 进入 `.dshbackup`，发布版本位于 `worlds/` 下并随世界文件一起备份。恢复后使用同一个 `stateRoot` 即可继续查看。

`doctor` 会报告数据库中存在但发布文件缺失的产物。缺失状态不会被伪装成可预览，也不会通过重新执行角色运行来补写外部结果。
