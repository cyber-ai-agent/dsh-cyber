# 世界产物中心 V1

世界产物中心用于保存角色或用户明确发布的工作成果。显式运行清单始终优先；清单缺失时，宿主只登记该 AgentRun 开始到完成时间窗口内在当前世界工作目录中真实新增或修改的普通文件，不根据聊天文字猜测产物，也不读取桌面或世界目录外的文件。

## 用户可见能力

- 右侧“产物”页按当前世界列出已发布成果，支持搜索、类型筛选、重命名、归档和版本查看。
- 聊天回复可以引用已登记的产物。点击产物卡会打开同一个世界中的产物详情。
- Markdown 使用文档阅读器显示标题、列表、引用、表格和代码块；代码、JSON、PDF、图片、HTML 和项目目录使用各自的阅读方式。
- HTML 预览运行在隔离沙箱中，不能访问 DSH Cyber 的应用接口或页面数据。
- 刷新页面或重启服务后，产物登记、版本和聊天引用仍可恢复。

“知识”页提供独立的原始资料库。产物不会自动进入知识库，只有用户明确执行“加入知识”时才建立带来源的知识文档。

## 权威数据与文件边界

SQLite 是产物身份、当前版本、状态、来源和运行关联的权威数据源。发布文件保存在对应世界目录中：

```text
<stateRoot>/worlds/<worldId>/
├─ files/                         # 世界工作目录
│  └─ .dsh/artifacts/             # 运行结束时写入的发布清单
└─ exports/artifacts/
   └─ <artifactId>/v<version>/    # 不可变的已发布版本
```

工作目录与发布目录承担不同职责：

- `files/` 中的源文件可以继续编辑；
- `exports/artifacts/` 中的版本是发布时快照，不随源文件变化；
- 删除或归档登记不会把工作目录中的源文件当作缓存清理；
- 世界隔离由 `worldId`、世界根目录和数据库外键共同保证。

## 角色运行后的发布流程

每次角色运行结束后，编排层调用一个与模型供应商无关的完成钩子。钩子优先读取该次运行对应的精确清单：

```text
files/.dsh/artifacts/<agentRunId>.json
```

清单中的每一项必须声明工作目录相对路径、名称和类型，也可以声明说明和项目入口文件。服务端会在发布前重新验证：

- 路径必须位于当前世界工作目录内；
- `.dsh` 管理目录不能作为产物来源；
- 符号链接、目录穿越、超出大小或文件数量上限的内容会被拒绝；
- 项目入口必须是项目目录内的普通文件；
- 文件内容和摘要必须与写入数据库的版本一致。

如果该次运行没有写入清单，宿主会使用已持久化的 AgentRun 开始/完成时间，仅收集这一时间窗口内发生变更的普通文件。自动登记继续遵守同一世界、路径、符号链接、大小与数量限制；超过 32 个候选文件时失败并要求运行写入显式清单，避免把整个工作区误登记为产物。显式空清单表示本轮明确不发布，不触发自动登记。

发布顺序是“验证 → 复制到临时目录 → 生成摘要 → 原子切换版本目录 → 写入 SQLite”。重复处理同一个运行清单使用稳定幂等键，不会生成重复版本。只有发布成功后，最终聊天消息才会写入 `artifactRefs`。

## 阅读器安全边界

预览接口只允许读取已登记版本中的文件：

- Markdown、文本、代码和 JSON 以受限文本响应返回；
- 图片和 PDF 使用浏览器原生预览；
- 项目先返回受限文件树，点击文件后再按精确相对路径读取；
- HTML 响应带严格内容安全策略，前端 `iframe` 不授予同源权限。

原始 Prompt、模型隐藏推理、API 密钥、Cookie、Authorization、任意工具输入和未发布的工作区内容不会进入产物登记或预览响应。

## 备份、恢复与诊断

产物元数据随 SQLite 进入 `.dshbackup`，发布版本位于 `worlds/` 下并随世界文件一起备份。恢复后使用同一个 `stateRoot` 即可继续查看。

`doctor` 会报告数据库中存在但发布文件缺失的产物。缺失状态不会被伪装成可预览，也不会通过重新执行角色运行来补写外部结果。
