# DSH 0.1.2 compatibility matrix

状态：当前运行时精确锁定 `@deepseek-ai/dsh` **0.1.2-rc.1**。上游截至 2026-09-05 没有正式稳定版；选择最新候选版，暂不采用标注历史会话性能回退的 0.1.3-alpha.1。

## 当前兼容结论

- 全部直接 DSH 依赖和 SDK/Bundle 使用 rc.1；候选检查拒绝旧 alpha 或混合版本。
- 审批桥接使用 `Session.seq` 和 `eventAt(SessionSeq)`，不再读取已移除的 `Session.events`；审批类型直接依赖上游类型，避免自造接口掩盖破坏性变更。
- 原生文件权限值保留 `read-only`、`workspace-write`、`danger-full-access`；用户名称为“只读访问／当前世界／完全访问”。当前世界对应世界的 `files` 目录；DSH 原生工作区策略还允许部分平台临时目录。审批只扩大本次操作，不改变持久授权。
- rc.1 SDK server 仍用 `agents.create()`，没有命名会话的冷恢复 RPC。因此继续在新 Worker 使用随机 ID，并从 SQLite 恢复有界历史；同进程会话只补未观察消息。
- 历史预算按最终 JSON 与指令包装估算；不重复保存同一内容的 `utterance`，超长消息带截断标记，小预算不能反向关闭限制。估算不代表模型的精确 tokenizer 计数。
- 真实 Worker 已验证两轮连续性、关闭重建后的单次恢复、候选 canary，以及只读拒写、项目内写入、项目外拒写、单次批准/拒绝和完全访问写入。

## Authority boundary

DSH Cyber 的 durable authority 仍是本地 SQLite 及其领域事实：`Employee`、`Dossier`、`Milestone`、`Conversation`（`WorkSession`/`WorkMessage`）、`WorkTurn`、`AgentRun` 和 `Knowledge`。DSH `Session`/JSONL、projection cache、Profile、Remote gateway、插件元数据和上传水位都只是 Harness 运行时缓存或外部集成证据，不能成为上述事实的第二个来源。

因此：

- 重启、升级、Profile 变更或 DSH session 日志损坏时，产品会话、角色档案、里程碑、工作回合、运行记录和知识必须从 DSH Cyber SQLite 恢复；
- DSH 的 `agentSessionId` 只能标识某个角色在某个会话中的运行时缓存。不得用员工全局的 `agentSessionId` 推断 `Conversation`，也不得把 DSH log 当作 `WorkMessage` 或 `DomainEvent`；
- 任何升级流程都必须保留 `stateRoot` 和完整 Backup Bundle，不删除或重新初始化本地事实。

## Required implementation order

1. 扩展 candidate compatibility contract：活动 candidate 仅为 alpha.3，并让所有直接 DSH package 精确 pin 同一版本；alpha.1/alpha.2 只用于审查变更来源，不作为可激活 runtime。
2. 先处理 session binding/lifecycle、notification normalization、cancel/approval 和 token usage，再接 image content blocks；任何新输入都必须在 DSH Cyber durable `WorkTurn`/`AgentRun` 事实之后进入 Harness。
3. 保持 `dsh_plugin_packages` 与 `dsh_session_log` 关闭，除非有单独的隐私、provider capability 和用户同意评审；它们不能进入默认 Cyber worker bundle。
4. 迁移旧 DSH log/backend 时只做可验证的 format migration/export；失败时保留原始目录并从 SQLite 恢复，不删除 `stateRoot`、SQLite、Workshop、Skill、assets 或 conversations。

## Test gate

alpha.3 candidate 必须通过：

- 静态合同：所有 DSH family package exact version、Profile manifest/patch、JSON-RPC method/envelope、SessionEvent version/ignorable、RemoteError mapping；
- Harness：initialize/close、session create/resume/fork、同会话队列、cancel/approval、child notification、usage、image block、long-history bounded replay、backend removal；
- Cyber integration：SQLite `Conversation`/`WorkTurn`/`AgentRun`/`Knowledge` counts 与归属不变，重启不重复 WorkTurn/message，Trace 脱敏，单世界单 `/live`；
- Provider matrix：official DeepSeek、local loopback、HTTPS remote OpenAI-compatible；metadata/upload fields 必须按 capability/consent fail closed；
- 浏览器/E2E：真实可见发送/停止/审批/附件入口，运行中追加文本和图片，群聊 discussion/task，reload/冷恢复，并记录 console error/warn；
- 升级回滚：先生成完整 `.dshbackup`，candidate canary 失败不切换 active runtime；原 DSH log、Cyber SQLite 和所有 stateRoot 子目录可由旧版本读取。

## Decision

Phase A 采用 0.1.2-alpha.3，并保留当前 SDK server 仍需要的随机 session id、SQLite 有界历史恢复和精确 collision retry。`session-log-deepseek`、`plugin-package-inventory-deepseek` 与 telemetry 在 DSH Cyber worker Profile 中默认关闭。最关键的兼容策略是：借用 DSH 的 runtime/session/Remote 能力，但永远不让 DSH 的 Session log、projection cache、plugin metadata 或远程上传取代 DSH Cyber 的 SQLite/Employee/Dossier/Milestone/Conversation/WorkTurn/AgentRun/Knowledge durable authority。
