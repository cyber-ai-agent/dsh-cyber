# DSH 升级与产品链路可靠性计划

## 目标与基线

从主线 `65217c1` 开始，在 `codex/dsh-rc1-compatibility` 完成升级、问题复现、逐项修复和真实交互验证。验收标准是用户意图能到达真实结果、失败可定位并可恢复，而不是页面存在或接口返回 200。

2026-09-05 核实：上游公开发行版全部标记为 prerelease，没有正式稳定版。本次选择最新候选版本 `0.1.2-rc.1`（`a66e470`），不采用有已知历史会话性能回退及 Session v2 迁移的 `0.1.3-alpha.1`。所有 DSH 依赖精确锁定同一版本。

## 架构边界

- 本地 SQLite 与世界文件仍是唯一业务事实源。DSH 负责模型与工具执行，其会话日志是可替换的运行时缓存。
- 用现有 `WorkTurn → AgentRun → CompletionJob` 串联执行与交付。完成聊天不等于产物已登记；各阶段有独立状态、错误和重试入口。
- 产物只能来自验证过的真实文件或宿主生成资产。统一经 `WorldArtifactService` 注册、版本化、预览；模型说“已生成”不算证据。
- 知识库保存可追溯的导入资料，图谱是来源支持的提取结果；角色私聊记忆单独维护，不能自动公开到世界知识。
- 图谱更新按来源变更触发，有界批次、合并短时间重复变更、单世界不重入、失败退避。保留手动刷新和可见的最后成功时间、待处理量与错误；频率由真实积压和成本决定，不盲目定时全量重算。
- 任务清单表达用户要求完成的工作，执行记录表达实际发生的事实，两者分开。意图识别可提出任务，创建应幂等且能关联原消息；任务的完成必须由交付或执行证据推动，不能由模型自行宣告。
- 日程复用任务/执行入口，执行前重新核对角色、权限和模型，以 `(scheduleId, scheduledFor)` 去重。重启不重放可能已有副作用的执行。
- 创意工坊保留 `source → generated package → preview → install → entity`，失败需要留下可编辑的草稿与诊断，不能留下半个世界。
- 市场目录、安装状态、世界实例三者分开。兼容模板的目录展示不能依赖是否已经安装；缺少入口、兼容性过滤和分页需分别检查。
- 前端所有结果区经同一个世界 `/live` 流失效刷新。世界切换、晚到响应、卸载重挂载和失败后重试纳入每项验收。
