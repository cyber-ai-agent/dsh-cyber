# 标准技能格式兼容与按需读取 V1

## 范围

让普通 `SKILL.md` 目录或 ZIP 进入现有技能中心，并复用原生包安装、世界引用、角色授权和工具执行边界。新增的是声明式内容适配和受控文档读取，不是另一套插件运行时。

V1 保持上游默认技能目录扫描关闭，不扫描用户目录、项目目录或全局技能根；也不直接启用上游通用技能发现工具。只有 Cyber 当前世界与角色允许的技能可以进入本轮目录。

## 导入

既有 `dsh-cyber.package.json`、`kind=skill` 导入继续走原生路径。没有原生清单时，标准目录需要唯一的根 `SKILL.md`；ZIP 可以保留一个共同外层目录。多技能根、重复或歧义路径、穿越和符号链接不能靠选择其中一个继续导入。

`SKILL.md` 使用 UTF-8 与 YAML frontmatter：

- `name`：小写字母、数字和单连字符组成的机器标识，最长 64 字符。
- `description`：用途与触发范围，最长 1024 字符。
- `license`：可选许可声明；不把缺失许可默认改成 MIT。
- `metadata`：可选字符串映射，用于保留来源、作者或发布者等信息；`display-name` 可提供中文展示名，机器标识仍取 `name`。这些字段不产生权限。
- `compatibility`、`allowed-tools`：可保留的来源声明，不安装依赖、不授予工具。

解析器拒绝非映射 frontmatter、重复键、不安全 YAML 构造及别名等。原始 `SKILL.md` 和同目录资源按原字节保存在生成包的 `source/` 下；宿主生成 `skill.json`、原生包清单和文件哈希。转换后的能力固定为 `skill:recipe`，`integrationId=builtin.recipe`，没有数据外发声明或执行回调。

来源内容哈希参与导入包和技能标识，相同输入得到相同标识，不同内容形成独立标识。V1 不猜测第三方发布者身份，也不自动把新内容替换成原角色已授权的技能版本。原始许可文件和来源资料随包保留；导入成功不等于宿主为第三方授权状态背书。

## 渐进读取

运行时分三层提供内容：

1. 每轮根据当前世界可用性、启用范围和角色 revision 的 `skillGrants`，生成名称、用途、标识与版本摘要。
2. 模型需要该工作方法时，经宿主受控读取工具取得正文；不再把全部已授权说明拼入每轮 Persona。
3. 仅在任务需要时读取正文返回的资源列表中的文本文件。原文相对链接不是宿主绝对路径，也不能变成任意文件读取入口。

宿主提供 `skills_list({ offset?, limit? })` 与 `skills_read({ skillId, path?, offset?, limit?, resourceOffset? })`。读取合同由 `SkillDocumentReadRequest` 描述：技能标识、可选资源路径、字符偏移、分页长度和资源列表偏移；默认请求 6000 字符，最多请求 12000 字符。为避免既有 Harness 结果裁剪器丢失正文，工具按完整 JSON 渲染预算缩短每页，使用响应的 `nextOffset` 继续读取；资源列表以 `nextResourceOffset` 作为下一次 `resourceOffset`，总数为 `totalResources`。默认正文路径是逻辑路径 `SKILL.md`；响应带有固定版本、实际路径、文本页、总字符数、后续偏移和可用资源路径。导入包的参考路径形如 `source/references/query.md`。调用方应复用响应的路径与分页值，不猜测文件位置。凭据脱敏先作用于完整文本，再进行分页；页码与总字符数描述脱敏后的内容。

内置 Recipe 和已有原生 Recipe 使用同一文档接口。未声明正文文件的原生 Recipe 从现有 `instructions` 提供正文；有声明时只读取包清单中的相应文件。

## 授权与完整性

目录是本轮发现快照，不是永久授权。正文与每个参考文件读取前后都重新检查角色是否仍有效、世界归属与状态、当前角色授权、世界启用范围及包可用性。

本轮文档读取固定到目录中的包版本与内容修订。运行中包被移除、替换或授权被撤销时停止读取；下一轮才能重新发现新版本。读取同时校验声明路径、包内边界和文件完整性，不能通过路径参数读取另一技能、另一个世界或宿主任意文件。

宿主与 Harness 之间使用每轮创建、结束时撤销的只读回环桥；地址和临时令牌只经私有协议传递，不进入模型消息、环境变量或轨迹。当前根代理及本轮由受信任运行时创建的子代理可以读取；跨轮存活的旧子代理及其后续子代理不会继承下一轮的读取能力。

文档是工作参考，不是新的系统指令层。`allowed-tools`、参考文件中的命令或资料里的授权文字不能批准操作。执行仍使用已有 Harness 文件与终端工具或受信任 Adapter，并受运行模式、角色与连接授权、动作审批和审计约束。

## 依赖与不支持的部分

- V1 不解释第三方安装脚本，不运行随包代码，不安装 CLI、语言包、模型或服务。
- 随包脚本即使被保留，也只是未执行的资源；能够读取脚本文本不等于允许执行。
- 二进制资源不能作为文本返回；文本读取有文件大小与分页限制。缺失、损坏、超限或不支持的资源明确失败。
- 标准格式中的环境和工具声明只提供线索，不映射成 Cyber 的 Skill Grant、Connection Grant、Capability 或系统权限。
- 不新增知识检索、知识写入、联网搜索、终端或发布能力。若任务依赖未提供的工具，角色应说明缺口并停在有证据的部分结果。
- 不创建后台任务、计划任务或持续文件监视。新的执行依赖需要单独设计宿主适配与授权，不能靠放进技能目录实现。

## 原创试点与验收

[开发任务流程](../../examples/skills/engineering-workflow/SKILL.md) 验证任务范围、计划执行与证据交付；[项目知识整理](../../examples/skills/project-knowledge/SKILL.md) 验证来源整理、有据问答和一致性检查。两个试点均为原创文本，不复制外部技能或脚本；各自携带仓库许可与来源说明。

应覆盖标准目录与 ZIP、原生包回归、多行正文、参考文件原字节保留、许可证缺失及声明保留、路径攻击、未授权和跨世界拒绝、运行中撤权、版本变化、缺失或损坏资源、分页，以及发现目录不含正文。具体试用和行为验收场景见 [示例说明](../../examples/skills/README.md)。格式测试通过不等于多步骤任务已经通过真实模型端到端验收。

实际 Harness 接线回归见 `packages/harness-adapter/tests/skill-document-harness.integration.test.ts`：启动仓库固定版本的真实 worker，使用本机确定性模拟模型驱动 `skills_list → skills_read → 回复`，检查正文仅在读取后进入请求、撤权拒绝、环境技能未被扫描、长文完整分页和私有桥数据不外泄。它验证协议和执行链，不代表两个试点在外部模型上的任务质量已完成验收。

运行校验：`pnpm run typecheck`、`pnpm run build`；接线用例可单独执行 `pnpm exec vitest run packages/harness-adapter/tests/skill-document-harness.integration.test.ts`。来源技能包的正文、引用和许可不能无损压缩成内联草稿，因此技能详情暂不提供“基于此技能新建”；修改来源目录后重新导入新内容，并重新确认角色授权。
