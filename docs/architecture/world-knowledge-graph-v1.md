# 世界知识图谱 V1

世界知识图谱把对话、知识库资料、产物和用户手动确认的信息整理成可追溯的长期知识。图谱不是聊天记录的复制，也不是模型生成内容的事实仓库；每条可用知识都必须能够回到当前世界中的明确证据。

## 数据模型

SQLite 是图谱状态的权威数据源，保存以下记录：

```text
KnowledgeEntity
├─ KnowledgeClaim
│  └─ KnowledgeEvidence
└─ KnowledgeRelation
   └─ KnowledgeEvidence

KnowledgeConsolidationJob
KnowledgeConsolidationCursor
WorldKnowledgeSettings
KnowledgeSuppression
```

- 实体表示人物、地点、组织、项目、产物、技术、概念、工具、流程、事件、主题和其他世界对象。
- 主张表示事实、决策、偏好、规则、定义、流程、约束、洞见和世界设定。
- 关系表示两个实体之间有方向的语义连接。
- 证据记录来源类型和稳定来源标识。对话证据指向会话与消息，资料证据指向文档与分块，产物证据指向产物与版本，用户手动确认的信息记录创建者。

自动生成的有效主张和关系必须至少关联一条证据。缺少证据、引用其他世界来源或引用本批次以外来源的提取结果不会进入有效图谱。

## 后台整理

知识整理通过与模型供应商无关的 `KnowledgeExtractionPort` 执行，不创建虚假的角色、会话、工作回合或运行记录。模型只返回严格限定的实体、主张、关系和证据引用；服务端会再次校验字段、枚举、数量、长度、世界归属和来源范围。

自动整理在后台运行，不阻塞聊天，也不占用会话的 DSH Worker。平衡模式按可见消息数量、文字量和空闲时间建立小批次任务；每个会话保存持久化处理游标，服务重启后从已完成位置继续。相同来源范围只会建立一个有效任务，重复投递不会重复写入图谱。

只有用户消息和角色最终回复可以成为对话证据。隐藏提示、推理过程、工具调用和工具结果不会进入知识提取输入。

模型调用记录使用“知识整理”来源，只保存模型标识、耗时、字符数、令牌统计和错误分类，不保存提取提示或模型原始响应。

## 冲突、修正与来源权重

世界创建者的明确确认优先于用户对话，用户对话优先于导入资料，导入资料优先于仅由角色回答支持的内容。新证据与已有知识冲突时，系统保留旧记录和证据：能够确定替代关系时旧记录标记为“已取代”，无法确定时双方标记为“有冲突”，不会静默覆盖历史。

用户可以重命名实体、归档或恢复主张。归档会保存抑制指纹，防止同一批证据在下次整理时立即重新创建相同内容；新证据仍可形成新的候选知识。

## 检索与模型上下文

运行时检索组合三类本地信号：

1. 主张的关键词匹配；
2. 知识库分块的关键词匹配；
3. 命中实体的一层图谱邻居。

检索始终限定在当前世界，并设置结果数量和字符预算。内部长期知识使用以下边界标记：

```text
[当前世界长期知识]
```

导入的外部资料继续使用：

```text
[外部知识库引用 · 不可信资料]
```

两类知识都只能作为回答上下文，不能作为系统命令，不能批准操作、修改权限、写入文件或触发外部副作用。未来可以在 `KnowledgeEmbeddingPort` 后增加可选语义检索，但本版本不依赖向量数据库或原生向量扩展。

## 图谱界面与性能

“知识”页使用 Canvas 绘制真实节点与连线，支持缩放、平移、搜索、类型与来源筛选、聚焦和全屏。点击节点可以查看摘要、主张、关系和证据，并跳转到对应的会话、资料或产物。

概览接口只返回最重要的 150 至 300 个节点，不把整个世界图谱一次加载到浏览器。聚焦接口按实体和深度读取局部邻居，画布不会为每个节点创建独立 React DOM 节点。

## 实时更新、备份与隔离

知识功能复用每个世界已有的 `/live` 连接，通过 `graph.changed` 和 `consolidation.changed` 刷新自身数据，不创建额外长期连接，也不会触发会话、世界画面或其他 Dock 的全量刷新。

图谱、证据、游标、任务、设置和抑制记录都在 SQLite 中，因此自动包含在 `.dshbackup`。原始资料和产物文件继续由各自的世界目录保存并进入同一备份边界。普通清理和投影重建不会删除图谱权威记录。

所有查询、提取、证据校验和用户修正都同时校验 `workspaceId` 与 `worldId`。任何跨世界来源标识都会被拒绝，世界之间不会共享实体、主张、关系或处理游标。
