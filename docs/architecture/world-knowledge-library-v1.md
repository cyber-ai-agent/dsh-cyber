# 世界知识库 V1

世界知识库用于保存当前世界需要长期参考的原始资料。资料可以来自本地文件、文件夹、ZIP 知识包、粘贴内容、公开网页或已发布产物。所有资料都保留来源、索引状态和更新时间，不把模型生成的摘要冒充原始证据。

## 用户可见能力

- 右侧“知识”页提供“知识图谱”和“知识库”两个视图。知识库已经可用，知识图谱在形成有证据的实体和关系后显示真实内容。
- 知识库支持 Markdown、TXT、JSON 和 PDF，并可以导入单个文件、文件夹、ZIP 知识包、粘贴内容和公开网页。
- 搜索结果始终限定在当前世界，并显示资料标题、来源路径和相关片段。
- 文件导入后立即建立文本分块和本地检索索引；页面刷新或服务重启后仍可搜索。
- 角色回答问题时可以在当前世界的知识库中完成一次本地检索。普通角色不需要获得原始知识文件读取权限。

## 权威数据与文件边界

原始资料文件是内容权威，保存在对应世界目录中：

```text
<stateRoot>/worlds/<worldId>/knowledge/library/
```

SQLite 保存集合、文档元数据和可重建的文本分块：

```text
KnowledgeCollection
└─ KnowledgeDocument
   └─ KnowledgeChunk
```

每条记录都带有 `worldId`。数据库查询、文件路径和 HTTP 接口都按世界约束，不会读取全部记录后再由前端筛选。

分块和全文索引属于派生投影，可以从原始文件重新建立。删除程序源码、更新依赖或替换运行时不会重新初始化用户的知识目录。

## 导入与解析

服务端负责解析和落盘，浏览器不加载 PDF 解析运行时。文本资料必须是有效 UTF-8；JSON 必须能够完整解析；PDF 使用服务端解析器提取可见文字。

资料正文按 Unicode 字符切分为约 800 至 1200 字符的片段，相邻片段保留约 100 至 150 字符的重叠。单文件大小、总导入大小、文件数量、目录深度、ZIP 条目数量和展开大小均有明确上限。

导入过程会拒绝：

- 绝对路径、Windows 盘符、UNC 路径和目录穿越；
- 编码后的穿越路径；
- 符号链接；
- 加密 ZIP、不支持的压缩方式和异常压缩比；
- 超出文件、目录或解压上限的内容。

目录扫描只检查知识库源目录中的变化。源文件缺失会把文档标记为“源文件缺失”，不会阻止应用启动，也不会重新执行角色任务来猜测内容。

## 本地检索与运行时上下文

SQLite 支持 FTS5 时使用可重建的全文索引；运行环境不支持 FTS5 时使用世界范围内的可移植 SQL 检索。能力检测不会让数据库迁移失败，也不要求安装原生向量扩展。

聊天热路径最多增加一次本地索引查询，不调用额外模型。检索选择少量最相关片段，并通过与模型供应商无关的运行时上下文组合器加入现有模型调用。

外部资料使用明确边界标记：

```text
[外部知识库引用 · 不可信资料]
```

资料中的命令、权限请求、审批文字和文件操作描述都只是被引用的正文，不能直接创建 Skill Action、修改世界权限、批准操作或写入宿主文件。轨迹只记录命中文档、分块标识、数量和分数，不保存完整检索正文或完整模型提示词。

## 网页导入与产物桥接

网页导入与 Firecrawl Skill 共用同一个受信任客户端和 Integration 连接。客户端统一处理凭据、超时、响应大小、错误分类和私有网络地址限制；API 密钥不会写入知识文档、SQLite 普通字段、日志或前端响应。

已发布产物可以由用户明确加入知识库。系统通过产物登记读取精确版本，不扫描整个工作目录，也不会让产物自动获得知识身份。

## 备份、恢复与诊断

`.dshbackup` 同时包含 SQLite 和 `worlds/*/knowledge/library`。恢复后可以从原始资料和数据库投影继续使用知识库。

`doctor` 报告集合、文档、分块和源文件缺失数量。缺失资料保持可诊断状态，不会被静默删除或伪装成有效索引。
