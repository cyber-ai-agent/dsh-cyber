# 验收与交付证据

适用于结束一个实现阶段或向用户交付结果时。简单任务用几句话即可，复杂任务再整理独立清单。

## 选择验证

- 领域规则、解析和纯函数：正常输入、边界、非法输入。
- 接口或权限边界：请求与响应合同、拒绝路径、隔离范围。
- 持久化：保存后重新读取；需要时验证重启恢复与旧数据保留。
- 交互改动：真实可见入口、完成、取消、重复操作和失败恢复。
- 并发或异步问题：最小可复现的交错、迟到结果和资源释放。

先遵守项目已有门禁，再补本次行为需要的检查。没有浏览器或相关运行环境时，静态阅读只能作为静态证据，不能替代界面或运行时验证。

## 证据记录

每条记录按需要包含：

- 对应的验收条件。
- 被检查的最终版本或工作树状态，以及执行时间。
- 实际检查入口、命令或人工操作。
- 可观察结果、退出码或脱敏后的日志位置。
- 状态：通过、失败、因条件不足而未运行。

不要编造计数、截图、退出码或工具返回。日志和截图避免暴露密钥、令牌及无关私人数据。临时工作文件不能冒充已保存、可访问的交付产物。

## 交付结构

1. 结果：哪些验收条件已满足。
2. 改动：关键文件或组件，以及行为变化。
3. 验证：实际通过和失败的检查。
4. 缺口：未运行的检查、风险、阻塞和下一步所需决定。

明确区分“本地已修改”“本地已验证”“已提交”“已发布”和“用户已验收”。只报告有证据的状态；一个阶段成功不能替代整个任务的完成条件。
